# D-24 楽観排他（412）発生後の UX

- **対応PBI**: [B-26](../progress.md)（方針）、[B-23](../progress.md)（ボードでの実装）
- **関連**: [D-20](./D-20-api-conventions.md)（`If-Match` 必須・412／428・「412 に最新値を含めるかは B-26 で決める」）、提案書 [Q-11](../proposal.html)、設計原則 **P-1**（ルールで縛らず、事実を見せる）、[D-13](../progress.md)（警告色を使わない）
- **決定日**: 2026-08-06
- **論点**: Open Questions **Q-F** — B-23 は 412 の**検出**を保証するが、**発生後どう振る舞うか**（自動再取得マージ／再操作を促す）が未定義。朝会の同時操作が前提のため体験を左右する。B-23 着手前に決める。

---

## 決定

| 項目 | 決定 |
|:---|:---|
| 方式 | **再操作を促す**。412 を受けたら**黙って上書きせず**、画面を最新に更新して人に判断を返す。**自動再取得マージは採らない** |
| 即時再取得 | 412 を受けた画面は**その場の集約 GET**（`/board`・`/backlog`）を引き直し、サーバーの状態を正として描画し直す |
| 事実の提示 | 「他の人が更新したため、最新の状態に更新しました。必要ならもう一度操作してください」を**事実として**示す。**警告色は使わない**（色は種別の区別のみ — D-13） |
| 412 応答本文 | **最新値を含めない**（D-20 の宿題への回答）。読み取りは画面単位で最新を取れるため、個別の最新値を本文に載せると「2 つの真実」が生まれる |
| 適用範囲 | ボードのドラッグ移動・ブロックフラグに加え、既存の書き込み操作（ステータス変更・並び替え・プランニング）**すべてで一貫**して適用する |

---

## なぜ「再操作を促す」なのか

**P-1「ルールで縛らず、事実を見せる」を UX にも適用する。**

自動再取得マージは、サーバーが受け取った競合を**アプリが勝手に解決する**ことを意味する。
ボードの状態遷移（`todo` / `doing` / `done`）は単純な移動に見えるが、「2 人が同じカードを
別の列へ動かした」ときに片方の操作を機械的に再適用すると、**もう意味を失った意図を
復活させうる**（相手が `done` にしたカードを、こちらの古い意図で `doing` に戻す等）。
これは「更新が黙って消える」を裏返しただけで、**人の知らないところで状態が決まる**点で
P-1 に反する。

朝会の同時操作という文脈では、**両者が「今どうなっているか」を即座に見られる**ことが最も
価値が高い。だから 412 を受けたら**間を置かず最新を描画し直し**、事実（誰かが更新した・
今はこう）を見せて、次の一手は人に委ねる。強制も警告もしない（P-1）。

## なぜ 412 本文に最新値を含めないのか

D-20 は「再取得マージ方式を採るなら含める価値があり、再操作を促す方式なら不要。ここでは
決めない」と保留していた。**再操作を促す方式に決めた以上、含めない。**

読み取りは**画面単位**（`GET /board` は 1 往復で全要素と `_etag` を返す — D-20）であり、
最新はいつでも 1 クエリで取れる。412 の本文に個別ドキュメントの最新値を載せると、集約 GET と
**別経路で最新が 2 つ**でき、しかも部分的（動かした 1 件だけ）なため画面全体の整合が取れない。
「二重の真実を作らない」（D-08）と一致させ、最新の源は集約 GET に一本化する。

## 実装の形（B-23 で書く）

412 の扱いは**各操作ハンドラに散らさず 1 か所に寄せる**（`If-Match` 欠落を 428 で構造的に
塞いだのと同じ発想 — D-20）。既存のバックログ画面が既に採っている
「`error` で `reportProblem`（サーバー由来メッセージ）→ 集約 GET を `load` で引き直す」
（`frontend/src/app/backlog/backlog.ts`）を**共通の 412 ハンドラ**として明示し、ボード
（B-23）も同じ経路を通す。412 とその他のエラー（422 等）で文言は分けるが、**「再取得して
事実を見せる」動きは共通**にする。

これで **B-26 の完了条件**「更新が黙って消える経路が存在しない」「ボード操作全体で一貫して
適用される」を満たす。

## 却下した案

| 却下した案 | 理由 |
|:---|:---|
| 自動再取得マージ | サーバー／アプリが競合を勝手に解決し、人の判断を奪う（P-1 違反）。ボードの状態遷移で「両者が同じカードを動かした」場合、意味を失った意図を再適用しうる。複雑さに見合わない |
| 412 応答本文に最新値を含める | 集約 GET が既に最新の唯一の源。部分的な最新値を別経路で返すと画面全体と整合せず、二重の真実になる（D-08） |
| Last-write-wins（`If-Match` を捨てる） | D-20 で却下済み。更新が黙って消え、しかも同時操作時にしか再現しない |
| 412 をモーダルでブロックして確認させる | 朝会のテンポを削ぐ。事実を見せて次の操作を妨げない方が P-1 に合う |
